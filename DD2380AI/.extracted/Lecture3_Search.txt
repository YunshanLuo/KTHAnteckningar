Problem solving via search
• A problem is composed of 4 components:
     •   An initial state
     •   Successor function, new_state = f(old_state, action)
     •   A goal test
     •   A path cost specification
• State space is the set of all states reachable from the initial state
• A solution is a sequence of actions.
• An optimal solution is a solution with minimum cost.

Avoid visited states
• Can speed up search.
• Must check for repeated states many times
    • Should be fast!


• Q: So how do we implement this efficiently?
    • We use a hash table, which gives us very fast lookups. Typically, constant time!

Hash table
• Want to find a way to know which of all previously visited states we should compare the new state to, so we do
  not have to compare to all
• Use hash function to map the state (“key”) into an index
• Often implemented as
                                  𝑖𝑛𝑑𝑒𝑥 = ℎ𝑎𝑠ℎ_𝑓𝑢𝑛𝑐𝑡𝑖𝑜𝑛(𝑘𝑒𝑦) % 𝑁
    where N is the number of buckets or bins and % is modulo, i.e. maps to index [0, N-1]



• Lots of hash functions have been suggested
    • For example, Zobrist hashing common in games

Iterative deepening search
• Number of nodes generated in a depth-limited search to depth d with branching factor b:
                            NDLS = b0 + b1 + b2 + … + bd-2 + bd-1 + bd

• Number of nodes generated in an iterative deepening search to depth d with branching factor
  b:
                    NIDS = (d+1)b0 + d b1 + (d-1)b2 + … + 3bd-2 +2bd-1 + 1bd

• For b = 10, d = 5,
    • NDLS = 1 + 10 + 100 + 1,000 + 10,000 + 100,000 = 111,111
    • NIDS = 6 + 50 + 400 + 3,000 + 20,000 + 100,000 = 123,456

• Overhead = (123,456 - 111,111)/111,111 = 11%

Properties of greedy best-first search
• Completeness: Could get stuck in loops; repeated-state checking needed to ensure completeness
• Time: O(bm) - a good heuristic can improve this significantly in practice
• Space: O(bm) - keep all nodes in memory
• Optimal: no

A* search
• Minimizing the total estimated solution cost
• Still widely used best-first method
     •   Robot Navigation and Planning
     •   Autonomous Driving
     •   Game AI
     •   Warehouse Logistics
     •   Drone Flight
• Evaluation function f (n) = g(n) + h(n)
     • g(n) the cost from start to node n, i.e. cost thus far
     • h(n) estimate of cost to get to goal
     • f (n) estimated total cost of reaching the goal from the start via node n

• A* is optimal if h(n) is an admissible heuristic
     • h(n) admissible if it does not overestimate the cost

• Complete: Yes
• Time: Exponential in length of solution
• Space: Keeps all nodes in memory
    • memory main problem
• Optimal: Yes (under certain conditions)

    •   Simple MA (SMA*)

Dominating heuristics
• Which of the heuristics is better?
     • h1(n): Number of misplaced tiles
     • h2(n): Sum of distance tiles from goal position (measured using city-block distance)
• The one that needs to expand less nodes before finding an optimal solution
• If h2(n) ≥ h1(n) for all n, then h2 dominates h1
• Dominating heuristics is generally better (it leads to fewer node expansions)
     • Careful with not overestimating (you lose optimality)

     • Analysis of sub-problems

     • Use of pattern databases

Local search: when the path does not matter.
Local search methods / Optimization Problems
• In some cases, the path is irrelevant
• The goal configuration itself is the solution, not the path to it
     • train schedule, factory-floor layout, N-queens
• State space is the set of possible configuration
• Uses only a single current state, paths are not retained, and we want to try to keep improving the current state
• Not systematic, but only little memory is needed and often find reasonable solutions

• Look at neighbors and move “uphill" in performance metric
