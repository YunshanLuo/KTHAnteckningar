Introduction to Games
• Some problems are multi-agent
    • Cooperative vs competitive interaction
• Search problems in these environments are called games
• In competitive environments also adversarial search
Why study games?
• Precise rules
• Limited number of actions
• They are hard problems!
• Example: Chess
    • Average branch factor of 35
    • Typically, 50 moves for each player
    • → 35100 ≈ 10154 nodes in search tree

Deterministic games: Go
• Enormous branch factor (b>300)

     •   Monte Carlo Tree Search explores the most promising moves during

• Turn-taking, two-player, zero-sum games
• Gain of winner same as loss of loser
Formalizing the problem: MAX and MIN
• Two players MAX and MIN
• An initial state (the start situation)
• A successor function (move, state)
• A terminal state - when is the game over?
• A utility (objective, payoff) function gives value for terminal state
          typically (+1,-1,0)
• The progression can be modeled as a (game-) tree
Game tree
(2-player, deterministic, turn-based)
Optimal strategies
• In “normal search”: reach the goal configuration
• In adversarial search: not enough, MAX needs to reach the goal
  configuration regardless of what MIN does
• Optimal strategy: at least as good as any other strategy when playing
  against an infallible MIN
Question
• Consider a 2-ply (half-move) game tree
    • MAX has actions a1,a2,a3 and MIN has actions b1,b2,b3, c1,c2,c3, d1,d2,d3




• What is the best strategy for MAX?
The best strategy
• If MAX picks a1 MIN will pick b1 → 3, if MAX picks a2 MIN will pick c1 → 2, a3 will give d3→2




               Best to pick a1 as it gives utility 3

Repeated states
• Transposition causes repeated states (among others)
    • Many different moves result in same configuration
    • Example: chess
• Store evaluation in transposition (hash) table
Handling resource limitations
• When search is cut off, use a heuristic evaluation function to estimate the value of the position
     • Should order cutoff states in a way that reflects their expected utility
     • Should be fast to compute
     • Should use features that are relevant to winning

          Chess: number of white pawns, black pawns, white queens, black queens, etc.
Handling resource limitations
• Cuttoff test in addition to terminal test
     • Limited depth search
     • Iterative deepening
α-β pruning
• Do we really need to analyze all nodes?
• Stop investigating branches that cannot affect the Minimax result, i.e. prune the tree
• Cuts down computations, but still gives the same Minimax result
α-β pruning
• α: best value MAX can guarantee so far (a lower bound)
• β: best value MIN can guarantee so far (an upper bound)
• found along the path till now

Properties of α-β pruning
• Complexity - depends heavily on order of evaluation.
• With perfect ordering O(bm/2)
• → Can then look twice as far into the game as minimax in the same time
Reordering in α-β pruning
• Try likely the best first
• Chess: captures, threats, forward moves, backward moves
• Estimate through limited DFS
• Repeat killer moves
Non-deterministic games
• Expectiminimax
    • Extends minimax to games with stochastic elements like
      dice rolls or card draws (e.g., Backgammon, Monopoly).
• Chance Nodes
    • Introduced between MAX and MIN layers to compute
      the expected value (probability-weighted average).
Games with imperfect information
• E.g., card games, where opponent's initial cards are unknown
• Typically, one can compute a probability for each possible deal
• Simple approximation:
    • compute the minimax value of each action in each deal
    • choose the action with highest expected value over all deals
Summary adversarial search
• Competitive environment
• Four components: initial state, successor function, terminal test, and utility function
• Deterministic, turn-taking, zero-sum games with perfect information
     • Minimax + α-β pruning to optimize search
• Use of evaluation functions to allow depth-limited search
• Today, computers are as good or better than humans at many different games
